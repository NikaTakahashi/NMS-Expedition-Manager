# 9 · Configuration & Data

Where everything lives, and what each file means.

## File map

```
<program directory>/                     (e.g. ~/Descargas/Expedition Manager)
├── expedition_manager/                  ← source code (the Python package)
├── assets/                              ← Logo.jpeg + ExpeditionManager.ico
├── ExpeditionManagerLibrary/            ← the 126-file library + manifest.json  (gitignored, generated)
├── data/sources/                        ← cached raw inputs from the GitHub repo (gitignored)
├── run.sh / run-gui.sh / run.bat / …    ← launchers (see Platforms)
└── *.example                            ← reference templates (config.txt.example, overrides.json.example)

<state dir>/                             (per-user, per-OS; see below)
├── config.txt                           ← user config (KEY=VALUE)
├── overrides.json                       ← OPTIONAL personal overrides
├── state.json                           ← current installation + cache + backup
├── custom/                              ← generated customization files
└── backups/                             ← original + archived season files
```

The program directory contains **only source code, assets and launchers** —
no per-user files. Everything that is personal (config, overrides, state,
backups) lives in the state directory:

| OS | State directory |
|---|---|
| Linux | `~/.local/share/expedition-manager/` |
| Windows | `%LOCALAPPDATA%\expedition-manager\` |
| macOS | `~/Library/Application Support/expedition-manager/` |

> **Migration:** versions ≤ S22-era kept `config.txt` and
> `overrides.json` in the program directory. On the first run after
> upgrading, both are **moved** into the state directory automatically
> (idempotent; nothing is copied twice or lost).

## `config.txt`

A tiny `KEY=VALUE` file, kept in the state directory, created automatically
on first run if missing (never overwritten once it exists, so the user owns
it). Two keys:

| Key | Meaning | Default |
|-----|---------|---------|
| `proton_prefix` | Proton prefix path used to find the cache (Linux). **Empty = auto-probe** the standard Steam locations. | `""` |
| `library_path` | Where the library lives. | `<program dir>/ExpeditionManagerLibrary` |

- It is plain text — edit by hand or via `./run.sh config`.
- `save_config()` **preserves any keys the user added by hand** (appends them
  at the bottom), so extending the config doesn't get clobbered.
- A legacy `config.json` (in the XDG config dir) and a legacy root-level
  `config.txt` (older versions) are **migrated once** into the state-dir
  `config.txt` if present, for backward compatibility.

## `state.json`

The *runtime* record of what's installed and where. Written by install/uninstall.
Typical content while an expedition is active:

```jsonc
{
  "installed": {
    "exp_id": "e05",
    "mode": "Redux",
    "difficulty": "Hardcore",
    "custom": { "CarnageMode": "true", "…": "…" }   // only if customized
  },
  "cache_dir":    "<…>/NMS/<steamid>/cache",
  "target_cache": "<…>/cache/SEASON_DATA_CACHE_S22.JSON",
  "backup_cache": "<state dir>/backups/SEASON_DATA_CACHE_S22.JSON_20260101_120000"
}
```

- `installed.custom` holds the **full** flat value set that was installed
  (preset + user tweaks) so the GUI can re-populate its form on next launch.
- The keys `installed`, `cache_dir`, `backup_cache`, `target_cache` are removed
  on uninstall (the `backups/` files themselves are kept on disk).
- An empty `{}` (or missing file) means "nothing installed."

## `overrides.json` (optional)

Personal house-rules, kept in the **state directory**, applied at
**sync time**, last in the pipeline, to the matching combinations. Format:

```jsonc
{
  "e05/Redux/Hardcore": {
    "some/path/in/json": "value",
    "toRemove/path": "[[removed]]",
    "toAppend/path": "[[append]] extra"
  }
}
```

It uses the same override language as the upstream patches (see
[Customization](05-customization.md#relationship-to-overridesjson) for how it
differs from the per-install `--custom` form).

## `data/sources/`

The **cache of raw upstream files** (the `expeditions.yml`, the per-version
base JSONs, the patch YAMLs, the preset JSONs, `customizations.yml`, …).
A normal sync reads from here without network; a **force resync** refetches.
Safe to delete (it will be re-downloaded), but doing so makes the next sync
need network.

## `manifest.json`

The 126-entry hash index of the library (see [The Library](02-library.md)).
Regenerated by every sync; the SHA-256 per file is the source of truth for
"up to date?".

## Backups and the "nothing is deleted" rule

Every install:
- **copies** the current live file to `backups/<name>_<timestamp>`, and
- **moves** any *older-season* live files into `backups/…_<timestamp>_archived`.

So `backups/` is a growing, append-only archive of everything the program has
ever displaced. It's safe to prune old entries by hand if you want to save
space — the *latest* backup for an active install is referenced by
`state.json` and must be kept while that install is in place.

## Reproducibility & what to back up

- The **library** and **`data/sources`** are fully regenerable from the
  upstream repo (just run a force sync).
- Your whole **state dir** is yours — it holds `config.txt`,
  `overrides.json`, the backups, and (critically) your *original* game
  cache. Back it up if the install matters: if you wipe it, uninstall
  can't restore the pristine cache.
